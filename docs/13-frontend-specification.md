- 문서 버전: 1.0 / 2026-10-26

## 1. 목적과 범위

실제 작성된 HTML 시안을 **구현 가능한 프론트엔드 기준 명세**로 고정한다. 기존 PHP 테마를 그대로 사용하라는 뜻은 아니다. 메인 시안을 근거로 공통 헤더·내비게이션·푸터·버튼·카드·반응형 및 접근성 규칙을 정의하여 나머지 19개 공개 경로에도 일관되게 확장한다.

**확인됨:** 시안의 HTML 구조, CSS 선언값, JavaScript 모바일 메뉴 토글, 외부 링크 URL.
**제안:** WordPress PHP 템플릿 분리, 디자인 토큰 구조화, 하위 페이지 적용.
**미확인:** 실제 운영 활성 테마, ACF/예약/문의 구현 주체, 실기기 사용성, 성능 및 색 대비 검사, 브랜드 확정 로고와 실제 이미지 자산.

이 문서는 기획·개발 기준이지 운영 배포 승인서가 아니다.

## 2. 정보 구조 및 주요 사용자 여정

**주 사용자 가설:** 작은 글씨와 복잡한 메뉴를 부담스러워할 수 있는 중·장년층 고객. 특정 연령층 전체가 동일한 능력이나 선호를 갖는다는 가정은 하지 않는다. 실제 사용자 테스트로 검증한다.

핵심 과업은 세 가지다: (1) 추모용 제품을 알아본다. (2) 기록물·기념물 제작 사례를 본다. (3) 주문·문의 페이지로 이동한다.

**시안 상단 PC 메뉴**: 제품 안내(`#categories`) / 제품 종류(`#products`) / 기술 소개(`#technology`) / 회사 소개(`/about/`) / 오시는 길(`/contact/`) / 문의하기(`/room/qu/`).

**시안 모바일 메뉴**: 위와 같은 메뉴를 펼침 메뉴로 노출한다. `menuToggle`을 눌러 `mobileNav`를 펼친다. 메뉴 안 링크를 누르면 닫히고 Escape 키로 닫으며, 761px 이상으로 바뀌면 자동으로 닫는다.

## 3. 디자인 토큰 — 실제 CSS 값

현재 단일 `<style>` 내부 `:root` 선언을 기준으로 기록한다. 브랜드 확정 색상은 아니며 아래 색상은 **HTML 시안의 구현값**이다.

| `--muted` | `#526069` | 본문 보조 글자 |
| `--brand` | `#145363` | 주요 버튼·강조 |
| `--brand-dark` | `#0c3c48` | hover·퀵 액세스 |
| `--paper` | `#ffffff` | 기본 배경 |

| `--focus` | `#e5a23d` | 키보드 포커스 링 |

주 폰트 스택: `Pretendard`, `Noto Sans KR`, `Malgun Gothic`, `system-ui`, `sans-serif`. 실제 웹폰트 파일은 포함되어 있지 않으므로 기기에서 대체 폰트가 나올 수 있다.

| 항목 | 실제 선언 |
|---|---|
| 기본 본문 | `18px`, `line-height: 1.7`, `word-break: keep-all` |
| 모바일 본문 | `18px`, `line-height: 1.65` |
| H1 | `clamp(36px, 5vw, 64px)`, 모바일 `clamp(35px, 9vw, 49px)` |
| H2 | `clamp(30px, 3.3vw, 44px)` |
| H3 | `clamp(22px, 2.2vw, 28px)` |
| 공통 버튼 | `font-size:18px`, `min-height:56px`, 2px 테두리, `border-radius:12px` |
| 컨테이너 | `min(100% - 48px, 1190px)`, 모바일 `min(100% - 36px, 1190px)` |
| PC 섹션 여백 | 위아래 `100px` |
| 모바일 섹션 여백 | 위아래 `66px` |
| 키보드 포커스 | `4px solid #e5a23d`, 오프셋 `3px` |

**개선 필요:** 시안의 `14px`, `13px`, `12px` 안내 문구와 모바일 보조 문구는 고연령층 사용성 목표에 맞는지 재검토한다. 특히 중요한 정보를 작은 글씨에만 넣지 않는다.

## 4. 공통 컴포넌트 계약

### 4.1 헤더 / 로고
- `.site-header`는 `position: sticky; top:0; z-index:60`.
- `.header-inner` 높이 PC 최소 84px, 모바일 최소 72px.
- `.logo-mark`는 CSS로 만든 **임시 마크**이므로 회사의 공식 로고로 오해하지 않는다. 실제 로고 확보 후 교체.
- PC `.desktop-nav`: 가로 링크, 주요 문의 CTA.
- 모바일 `.menu-toggle`: 최소 `54×50px`, 누르면 `#mobileNav` 표시.
- 스크롤 앵커 보정: PC `scroll-padding-top:88px`, 모바일 `72px`.
- **개선 필요:** 열릴 때 첫 링크로 포커스 이동, 닫힐 때 포커스 복귀, 메뉴 외부 클릭 시 동작, 현재 위치 표기, 메뉴 열림 상태에서 배경 탐색 동작 등을 실기기로 점검한다.

### 4.2 버튼
- `.btn`, `.btn-primary`, `.btn-light`, `.btn-outline` 사용.
- 주요 CTA는 명확한 동사형 라벨을 쓴다. 링크는 실제 이동, 버튼은 명령 조작에 사용.
- hover는 `translateY(-2px)`·배경색 변화를 사용. `prefers-reduced-motion`에서 효과를 제거.
- `:focus-visible`을 반드시 유지.

### 4.3 카드 / 제품 바로가기
- `.category-grid`: PC 2열, 모바일 1열.
- `.category-card`: 제품군 미디어 → 제목 → 요약 → 전체보기 CTA.
- `.product-grid`: PC 3열, 1000px 이하 2열, 760px 이하 1열.
- `.product-link`: PC 최소 높이 116px, 모바일 최소 92px. 제목과 보조 설명을 함께 표시.
- 제품의 전체 클릭 영역과 링크의 실제 목적지를 일치시킨다.
- 실제 제품 이미지로 교체할 때 `width`/`height`, `alt`, `srcset`·`sizes`, 상황에 맞는 `object-fit`을 지정한다.

### 4.4 푸터
- `.footer` 진한 차콜 배경, `.footer-links` 일반 링크.
- 시안의 회사 설명과 저작권 표기는 **실제 운영 정보가 아님**. 기존 회사 주소, 전화, 이메일, 사업자 정보, 개인정보처리방침 및 최신 연도를 별도로 확인.
- 모바일에서는 하단 액션 바와 겹치지 않도록 푸터 바닥 패딩 `125px`.

### 4.5 모바일 고정 액션
- `.mobile-action`: 760px 이하에서만 표시, 하단 고정 2열(`주문하기`, `문의하기`).
- 각 버튼 최소 높이 `57px`, 글씨 `17px`.
- `env(safe-area-inset-bottom)`을 고려하되 실제 iOS/Android 환경에서 화면 가림, 키보드 표시, 확대 및 접근성 검사 필요.
- 개인정보 수집 폼 등의 화면에서는 필요에 따라 숨기거나 동작 조정 검토.

## 5. 반응형 동작

| 조건 | 실제 CSS 변경 |
|---|---|
| `>1000px` | PC 전체 내비게이션, 메인 2열, 제품 3열 |
| `≤1000px` | 내비게이션 간격·글자 축소, 제품 2열 |
| `≤760px` | 보조 탑라인 숨김, 모바일 메뉴 표시, 메인·카테고리·제품·절차 1열, 하단 고정 액션 표시 |
| 모션 감소 설정 | 스크롤 애니메이션·transition·animation 제거 |

**테스트 폭:** 320, 360, 390, 430, 768, 1024, 1440px 및 200%/400% 확대. 320px의 좁은 화면에서 로고·메뉴·하단 CTA 줄바꿈과 겹침을 우선 점검. 760~1000px에서 줄어든 PC 메뉴가 좁아지는지도 점검.

## 6. JavaScript 동작 계약

시안은 외부 라이브러리 없이 하나의 스크립트로 모바일 메뉴를 제어한다.

- `setMenu(open)` → `aria-expanded`, `aria-label`, `hidden`, `.is-open` 동기화.
- `#menuToggle` 클릭 → 열림/닫힘 전환.
- `#mobileNav` 안 링크 클릭 → 메뉴 닫음.
- `Escape` 입력 → 메뉴 닫고 토글 버튼으로 포커스 반환.
- `(min-width:761px)` 미디어 쿼리 변화 → 메뉴 닫음.

**구현 보강:** 기존 상태에서 `aria-controls` 등 접근성 연결 검증, 메뉴 내외부 탭 이동 순서 확인. 페이지 링크 자체는 브라우저 기본 이동을 유지한다.

## 8. WordPress 구현으로 이관할 때

현재 HTML은 실제 WordPress 테마가 아니다. 기존 DB·예약·ACF·문의 기능은 연결되어 있지 않다.

**추천 파일 분리안(미확정):**

```text
 development/metalphoto-theme/
 ├── style.css
 ├── functions.php
 ├── header.php                 # 공통 헤더·모바일 메뉴
 ├── footer.php                 # 공통 푸터·모바일 고정 CTA
 ├── front-page.php             # 본 시안의 메인 섹션
 ├── page.php                   # 일반 페이지
 ├── single-room_post.php       # 기존 room 게시물 상세(보존 확인 후)
 ├── template-parts/
 │   ├── sections/
 │   ├── components/
 │   └── navigation/
 └── assets/
     ├── css/tokens.css
     ├── css/base.css
     ├── css/components.css
     ├── css/layout.css
     └── js/navigation.js
```

- `wp_head()`, `wp_footer()`, `body_class()`, `wp_nav_menu()` 등 WordPress 연결 지점을 보존.
- 메뉴 텍스트 및 상세 링크를 하드코딩한 시안과 달리 최종 테마에서는 WordPress 메뉴·콘텐츠에서 관리 가능한 항목을 정의한다.
- 활성 Holiday 테마 / `room_post` / ACF / 예약 / Contact Form 7 및 자체 문의 처리의 실제 의존성을 확인하기 전 테마 교체를 실행하지 않는다.
- 로컬 복원과 회귀 테스트가 가능해진 뒤 화면과 데이터를 연결한다.
- 프로젝트 원본 테마(`themes/`)는 수정하지 않는다.

## 9. 고연령층 모바일 UX 검수 체크리스트

- [ ] 필수 정보의 본문 글자 크기가 충분한가? (기본 18px 유지, 보조 12~14px 개선 검토)
- [ ] 모든 주요 클릭 요소의 터치 크기와 간격이 충분한가? (권장 약 48~56px 이상)
- [ ] 제품군 2개와 `주문하기/문의하기`를 첫 화면에서 쉽게 찾는가?
- [ ] 제품별 이름이 쉬운 한국어로 설명되는가? (VIP폴 등 용어 보충)
- [ ] 200%/400% 확대 시 텍스트가 겹치거나 사라지지 않는가?
- [ ] 키보드로 열기/닫기, 제품 탐색, 문의 이동이 가능한가?
- [ ] 색상 외에도 현재 메뉴 위치·상태를 알 수 있는가?
- [ ] 고정 하단 바가 폼 제출 버튼이나 콘텐츠를 가리지 않는가?
- [ ] 색상 대비가 WCAG AA에 부합하는가? (도구로 측정 필요)
- [ ] 실사용자 3~5명 이상에게 제품 탐색과 문의 과업을 테스트했는가? (소규모 초기 테스트 제안)
- [ ] 고객이 모바일에서 기존 문의/주문 페이지로 이동한 뒤 이탈하지 않는가?

| P1 | `≤1000px`에서 PC 메뉴 글자가 14px로 작아짐 | 태블릿에서도 모바일 메뉴 전환 시점 앞당길지 시험 |
| P1 | 모바일 메뉴 포커스·스크린리더 완결성 실측 없음 | 키보드·VoiceOver/TalkBack 검증 |

## 11. 수용 기준(Definition of Done)

**디자인 승인:** 모바일 360/390/430px에서 읽기 쉽고, 제품군→상세→문의의 과업 테스트를 통과한다. 실제 로고·사진·문구 승인을 받는다.

**개발 승인:** WordPress 로컬 환경에서 헤더/푸터/메인/하위 템플릿이 정상 동작하고, 모든 관련 기존 URL·메뉴·게시물·ACF·폼 기능의 회귀 테스트를 통과한다.

**배포 승인:** 운영과 격리된 검수 환경, 민감정보 제외, 백업·복원 검증, 고객 문의 데이터 보존, 명시적 사용자 승인 이후 별도 수행한다.

## 12. Codex 작업 지시 원칙

1. 이 명세와 기준 HTML을 읽고 **시안 값과 새로운 제안**을 구분한다.
2. 공통 디자인 토큰·헤더·푸터·컴포넌트를 재사용한다.
3. 먼저 메인 시안을 로컬에서 정적 구현·검증한다. 운영 WordPress에 바로 적용하지 않는다.
4. 페이지별 작업에 착수하기 전 기존 URL·콘텐츠·연동 의존성을 확인한다.
5. 디자인 구현 작업 결과는 변경 파일·동작 확인 방법·미구현 기능을 명시한다.
6. 자동 업로드·운영 DB 접속·강제 Push를 하지 않는다.
