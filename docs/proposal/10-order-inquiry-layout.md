# 주문 방법·문의 구성 제안

작성일: 2026-10-26 (KST) · 상태: **내부 검토용 Draft / 미승인**

상태 구분: **AS-IS**는 PHASE A에서 수집한 소스의 사실, **ISSUE**는 PHASE B의 문제 또는 검증 가설, **TO-BE**는 신규 제안, **APPROVAL REQUIRED**는 내부 컨펌 필요, **UNVERIFIED**는 추가 검증 필요다. 제안 수치·문구·화면 순서는 승인된 확정값이 아니다. 화면 렌더링·이미지 실물·모바일 동작을 검증한 것으로 취급하지 않는다.

공통 수치는 [디자인 시스템](02-design-system.md), 요소 계약은 [공통 컴포넌트](05-shared-components.md), 경로는 [사이트맵](01-information-architecture.md)을 따른다. 아래 추가 항목은 실제 기존 콘텐츠가 아니라 확보 조건이 붙은 제안이다.

<a id="p19"></a>

## P19 — 주문하기

- 기존 URL 유지: http://www.gomemo.net/order_question/
- 근거: [PHASE A 19](../audit/19-page.md)의 「개별 콘텐츠 — 소스 등장 순서」「이미지 참조 및 소스상 위치」, [PHASE B A19](../evaluation/05-order-inquiry-evaluation.md#a19).

### AS-IS — 목적과 실제 콘텐츠

목적 해석: 이메일 주문에 필요한 정보·사진·일정·조건을 안내하는 목적.

확인 사실: 이메일로 주문서와 사진을 보내도록 안내하며 필수 항목·원본/우편 전달·제작 기간·상담·공지 순으로 이어진다. 본문에 주문 입력 폼은 추출되지 않았다.

### ISSUE — 기존 평가와 한계

주문 CTA를 눌렀을 때 온라인 접수 대신 외부 메일 작성이 필요하므로 기대 불일치와 수기 누락 위험. 예상 영향: 사진 첨부·양식 복사·규격 전달 중 이탈하거나 주문 정보를 빠뜨릴 수 있다. 이는 검증 가설이며 이미지 내부 정보와 실제 화면의 결함을 확정한 것이 아니다.

### TO-BE — 페이지별 구성 제안

| 항목 | 내부 검토안 |
|---|---|
| 1. 신규 섹션 순서 | 이메일 주문임을 알림 → 준비 항목 → 원본사진/우편 전달 → 주문 양식 원문·복사 후보 → 제작기간/상담 → 취소·수정·공지 |
| 2. 유지할 콘텐츠 | 메일 제목·필수항목·사진/우편·제작기간·업무시간·수정/반품 정책 원문 모두 보존 |
| 3. 재배치·강조 | 안내를 과업 단위로 나누되 정책 숨기지 않음. 필수사항과 선택사항은 담당자 확인 전 구별하지 않음 |
| 4. 추가 콘텐츠·확보 조건 | 양식 복사문·전송 후 접수 절차: 담당자 승인 필요. 새 납기/응답시간 생성 금지 |
| 5. 이미지·갤러리 | 원본사진 준비 안내 중심; 예시 사진 추가는 실제 자료와 사용권 확보 후 |
| 6. 공통 컴포넌트 | C01·C06·C07·C08·C09 — [컴포넌트 계약](05-shared-components.md) 참조 |
| 7. 모바일 레이아웃 | 1열 준비 목록·복사·이메일 열기 후보, 공지 펼침 여부는 중요성 검토 |
| 8. 다음 행동 | 이메일 작성(운영 연동은 이후) 또는 문의하기 |
| 9. 탐색 진입 | 주문·문의 > 주문 방법 및 공통 전체 메뉴. 상세는 상위 목록 복귀 링크도 제공 후보 |
| 10. 유지·통합 판정 | 페이지와 URL 유지. 공통 안내는 표현·관리 단위만 통합 후보이며 별도 페이지 삭제/redirect 없음 |

### APPROVAL REQUIRED

기존 절차·라벨·정책 최신성·수기 주문 유지·접수 확인. 원문 유지 범위·추가 설명·이미지 배정과 다음 행동의 우선순위를 컨펌해야 한다. 담당자와 승인자는 미지정이다.

### UNVERIFIED

메일 앱 전환·양식 복사 과업, 담당자 최신 정책, 모의 접수 확인. 실제 규격·가격·재고·사례 내용·새 문구를 이 문서에서 생성하지 않는다. 추가 정보가 없으면 PHASE D에서는 「자료 확인 필요」로 표시하고 사실을 채워 넣지 않는다.

## P20 — 문의하기

- 기존 URL 유지: http://www.gomemo.net/room/qu/
- 근거: [PHASE A 20](../audit/20-page.md)의 「개별 콘텐츠 — 소스 등장 순서」「이미지 참조 및 소스상 위치」, [PHASE B A20](../evaluation/05-order-inquiry-evaluation.md#a20).

### AS-IS — 목적과 실제 콘텐츠

목적 해석: 연락 정보·문의·첨부를 접수하는 목적.

확인 사실: title은 qu, 본문은 문의접수/문의하기. 이름·tel·email·문의사항 type=text·jpg 파일·보내기와 첨부 실패 시 이메일 안내가 있다.

### ISSUE — 기존 평가와 한계

문서 제목이 목적을 설명하지 못함. 긴 문의 입력·첨부 제한·오류/성공 안내와 라벨 연결은 미검증. 예상 영향: 탭/방문기록에서 페이지를 찾기 어렵거나 긴 문의·첨부 단계에서 부담이 생길 수 있다. 이는 검증 가설이며 이미지 내부 정보와 실제 화면의 결함을 확정한 것이 아니다.

### TO-BE — 페이지별 구성 제안

| 항목 | 내부 검토안 |
|---|---|
| 1. 신규 섹션 순서 | 목적·주문 방법과 구분 → 준비/입력 안내 → 이름·연락처·이메일·문의·첨부 → 수집 안내 후보 → 보내기 → 결과/복구 상태 후보 → 이메일 대안 |
| 2. 유지할 콘텐츠 | 기존 입력 범주·jpg 첨부 안내·보내기·첨부 실패 이메일 대안 보존 |
| 3. 재배치·강조 | 명확한 페이지 제목·긴 문의 입력·오류/첨부 조건을 강조하는 후보 |
| 4. 추가 콘텐츠·확보 조건 | 필수항목·크기/형식·개인정보 안내·실제 결과문: 기능 담당자 확인/승인 필요 |
| 5. 이미지·갤러리 | 장식 제품 사진은 필수 아님. 첨부 미리보기는 구현 가능성과 개인정보 처리 확인 후 |
| 6. 공통 컴포넌트 | C01·C06·C08·C10 — [컴포넌트 계약](05-shared-components.md) 참조 |
| 7. 모바일 레이아웃 | 1열 입력, 문의는 여러 줄 후보, 키보드 중 하단바 숨김, 오류 위치로 이동 |
| 8. 다음 행동 | 보내기(미리보기는 비전송)·이메일 대안·주문 방법 |
| 9. 탐색 진입 | 주문·문의 > 문의하기 및 공통 전체 메뉴. 상세는 상위 목록 복귀 링크도 제공 후보 |
| 10. 유지·통합 판정 | 페이지와 URL 유지. 공통 안내는 표현·관리 단위만 통합 후보이며 별도 페이지 삭제/redirect 없음 |

### APPROVAL REQUIRED

기능·처리 주체·첨부 제한·개인정보·성공/오류 문구. 원문 유지 범위·추가 설명·이미지 배정과 다음 행동의 우선순위를 컨펌해야 한다. 담당자와 승인자는 미지정이다.

### UNVERIFIED

접근 가능한 이름·필수/오류·첨부 제한·개인정보 안내·격리된 모의 발송. 실제 규격·가격·재고·사례 내용·새 문구를 이 문서에서 생성하지 않는다. 추가 정보가 없으면 PHASE D에서는 「자료 확인 필요」로 표시하고 사실을 채워 넣지 않는다.

## TO-BE — ORDER01 채널·상태 제안

상세에서 「주문 방법 확인」으로 P19 이동 → 원문 양식 준비 → 사용자가 이메일 작성. 스토어는 「외부 스토어 보기」 후보로 구별하고 실제 상품 대응 확인 전 직접 구매를 보장하지 않는다. 문의 P20은 질문 접수이며 주문 완료를 대신하지 않는다.

P20은 빈 화면·입력 중·형식 오류·첨부 오류·전송 대기·실패·성공·이메일 대안 상태를 설계 후보로 둔다. 성공 문구는 실제 서버 접수 조건 확인 후 결정한다. PHASE D는 「전송되지 않는 시안」 표시와 모의 상태만 제공하고 실제 form action·메일 전송·첨부 업로드를 연결하지 않는다. 개인정보 안내와 필수 여부는 임의 생성하지 않는다.

근거: [OI01~05](../evaluation/05-order-inquiry-evaluation.md). 이메일 주문 절차를 온라인 결제·장바구니로 바꾸는 것은 기본 제안에 포함하지 않는다.
