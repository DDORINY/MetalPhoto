# 실제 개발 착수 준비와 컨펌

작성일: 2026-10-29 (KST) · 상태: 사전 분석 / 구현·배포 미승인

**확인**은 로컬 코드 또는 기존 audit의 수집 사실, **후보/추정**은 구조 일치에 따른 해석, **미확인**은 운영 설정·DB·실행 검증이 필요한 항목이다. Holiday의 실제 활성 여부는 미확인이다. 서버·DB에 접속하거나 PHP를 실행하지 않았으며 새 백엔드·테마·UI를 구현하지 않았다.

## 현재 판정

**아직 실제 WordPress 프론트엔드 개발 착수 조건을 충족하지 않았다.** 내부 디자인 미승인, 실제 활성 테마·필드/플러그인 의존성과 DB·이미지·관리 편집 경로가 미확인이다. 분석 문서나 정적 preview가 있다는 이유로 운영 코드 변경을 시작하지 않는다.

## 내부 컨펌 체크리스트

- [ ] 기존 백엔드 유지의 범위를 확인했다. 새 저장/전송·CPT 재설계·필드/DB 이동을 기본 변경에 넣지 않는다.
- [ ] [AP01~AP11](../proposal/13-approval-checklist.md)에서 메뉴·페이지 순서·큰 글씨·버튼·사진 확대·회사정보·정책·CTA를 검토했다.
- [ ] [페이지 매핑](02-template-page-mapping.md)의 실제 배정/관리 편집 위치를 확인했다.
- [ ] [수정 경계](04-frontend-modification-boundaries.md)에서 DOM/JS/폼 계약까지 기능 연결로 분류했다.
- [ ] 미리보기의 mock 폼·placeholder·CSP·원문 배열을 운영에 그대로 옮기지 않는다.
- [ ] 승인된 로컬 환경에서 [회귀 계획](06-regression-test-plan.md)을 수행할 담당자·합격 기준을 정했다.
- [ ] 보안 문제가 발견되면 기존 결함을 조용히 복제하거나 새 기능으로 우회하지 않고 별도 범위를 결정한다.
- [ ] 실제 기능 개발·서버 접속·배포·Git 작업은 각각 해당 사용자 지시를 확인한다.

체크는 현재 완료 표시가 아니다. 승인자·자료 제공자·테스트 담당자는 미지정이다. 제공 시 비밀번호·wp-config 원문·토큰·실제 고객 레코드는 대화/공개 저장소/문서에 넣지 않는다.

## 이후 순서 제안

자료 확보와 승인 → 로컬 기존 동작 재현 → 페이지/필드/이벤트 계약 확정 → A/B/C 선택 → 승인된 범위의 표시 코드 변경 → 관리자/기능/접근성 회귀 → 별도 배포 검토 순서다. 현재는 사전 문서화까지만 수행했다.
