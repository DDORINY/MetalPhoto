# 개발 방식 비교와 조건부 권장 방향

작성일: 2026-10-29 (KST) · 상태: 사전 분석 / 구현·배포 미승인

**확인**은 로컬 코드 또는 기존 audit의 수집 사실, **후보/추정**은 구조 일치에 따른 해석, **미확인**은 운영 설정·DB·실행 검증이 필요한 항목이다. Holiday의 실제 활성 여부는 미확인이다. 서버·DB에 접속하거나 PHP를 실행하지 않았으며 새 백엔드·테마·UI를 구현하지 않았다.

## 비교의 전제

[기존 평가](../02-theme-architecture-evaluation.md)를 현재 사용자의 **새 백엔드 개발 없음·기존 데이터/처리 유지** 원칙으로 좁혀 검토한다. 외형의 자유도만으로 독립 테마를 선택하지 않는다. [의존성](03-backend-dependencies.md)에서 테마가 CPT·ACF·예약·쇼트코드를 함께 등록함을 확인했다.

| 기준 | A. 활성 테마 직접 수정 | B. 활성 테마 Child Theme | C. 기능 보존 독립 테마 |
|---|---|---|---|
| 기존 기능 유지 | include가 남으면 유지 가능, 수정 실수 위험 | 부모 기능을 유지할 수 있어 우선 검토 후보 | 부모가 로드되지 않아 누락 위험 가장 큼 |
| PHP·ACF·플러그인 | 기존 전제 유지, 함수 충돌/본문 훼손 주의 | 부모와 함수 중복·리소스 순서·override 범위 검증 | CPT/ACF/폼·관리 UI 소유 주체까지 검증해야 함 |
| 유지보수 | 다운로드 원본과 차이 추적이 어려움 | 변경 분리·리뷰에 유리하나 부모 의존은 지속 | 표시 구조는 명확하나 기능 유지 책임·중복 코드 증가 |
| 업데이트 | 변경 유실·충돌 위험 | 부모 업데이트의 템플릿·선택자 변경 회귀 | 자동 해결 아님. 고정 복사한 기능의 보안/호환 추적 필요 |
| 디자인 자유도 | 구조 수정 가능하나 원본 결합 | override 가능한 템플릿 범위에서 높음 | 높지만 백엔드 유지가 자동 보장되지 않음 |
| 개발·테스트 | 외형과 기능을 함께 건드리기 쉬움 | 상대적으로 경계 명확, 그래도 전체 회귀 필요 | 전송·조회·관리·미디어까지 가장 넓은 검증 |
| 배포·롤백 | 원본 차이·옵션까지 복구 계획 | 부모/자식·설정·위젯 배정 복구 필요 | 테마 전환에 따른 옵션·메뉴·위젯·등록 복구 필요 |
| 현재 실행 | 미승인·금지 | 미승인·후보 검토만 | 미승인·우선 선택 근거 부족 |

## 조건부 권장

실제 활성 구성이 Holiday 단독 부모로 확인되고 템플릿 override로 목표를 표현할 수 있다면 **B를 우선 검토**한다. 원본 themes/를 수정하지 않고 개발 복사본에서 PHP 출력과 기능 계약을 유지한 표시 변경 범위를 시험하는 방향이다. 최종 결정을 내리거나 Child Theme를 생성한 것은 아니다.

- functions.php는 부모의 것을 덮어쓴다고 가정하지 않는다. 부모 코드를 통째로 복사하면 register_posts 등 전역 함수 중복 선언과 hook 중복 위험이 있다.
- get_template_part로 읽는 표시 파일은 후보이지만 includes/*.php의 고정 include는 같은 이름의 자식 파일을 두는 것만으로 대체되지 않는다.
- Holiday는 get_template_directory_uri를 리소스에 사용하고 get_stylesheet_uri도 사용한다. 부모 리소스·자식 CSS의 실제 로딩 순서를 확인해야 한다.
- 활성 테마가 Notes and Photos이면 이미 Blogrid 자식이다. 추가 세대 자식 구조를 전제로 하지 않고 현재 구조를 다시 평가한다.
- 사용자의 기존 백엔드 불변 조건에서 새 기능 플러그인을 만들어 등록·처리를 이전하는 안은 기본 범위가 아니다. 이전 문서의 장기 분리 제안도 현 단계에서 실행하지 않는다.

## 독립 테마 선택의 문턱

C를 선택하려면 기존 기능이 이미 별도 플러그인에서 제공되거나, 기존 등록/필드/처리 코드를 바꾸지 않고 유지할 수 있는 구체적 호환 경로와 회귀 증거가 필요하다. 단순 parent functions.php include는 동시 theme context·URI·중복 로딩 때문에 보존 증거가 아니다.

필수 기능을 떼어내거나 새로 구현해야만 가능하면 현재 요청 범위를 넘는다. 그 경우 독립 테마를 강행하지 않고 구조 선택·범위 변경을 보고한다. DB가 남아 있다는 것과 관리/URL/조회/전송이 살아 있다는 것은 별개다.

## 결정 대기

활성 테마·운영본 차이·실제 CPT/ACF/폼 제공자·부모 업데이트 정책·격리 회귀·컨펌된 화면이 필요하다. A/B/C 어느 방식도 기능·운영 롤백을 지금 보증하지 않는다.
