# 기존 기능·관리 편집 회귀 테스트 계획

작성일: 2026-10-29 (KST) · 상태: 사전 분석 / 구현·배포 미승인

**확인**은 로컬 코드 또는 기존 audit의 수집 사실, **후보/추정**은 구조 일치에 따른 해석, **미확인**은 운영 설정·DB·실행 검증이 필요한 항목이다. Holiday의 실제 활성 여부는 미확인이다. 서버·DB에 접속하거나 PHP를 실행하지 않았으며 새 백엔드·테마·UI를 구현하지 않았다.

## 실행 조건

테스트는 아직 수행하지 않았다. 기존 자료를 안전하게 복원한 로컬/검수 환경과 테스트 수신함을 준비한 뒤 합성 데이터로만 실행한다. 운영 DB 연결·실제 고객 메일·문자·결제·외부 추적·cron/webhook 실행은 차단한다. '읽기 테스트'도 WP 초기화가 DB 생성이나 외부 요청을 일으킬 수 있으므로 실행 환경과 실제 기존 기능 경로를 분리 점검한다.

기능 보존 기준은 기존 로컬 복원본의 동작이다. preview의 361개 검사는 정적 시안 결과일 뿐 PHP·관리자·폼·메일 회귀 통과로 재사용하지 않는다.

RT06은 사이트에 접수 저장 기능이 있다고 가정하지 않는다. 실제 저장 플러그인 유무·메일 성공 조건을 먼저 확인한다. wp_mail 반환 성공과 최종 수신은 별도 검증한다. RT07에서 관리 삭제·예약 테스트는 복사본에서만 하며 원복/고객 데이터 사용 금지다.

## 페이지별 편집 검증 범위

[20개 매핑](02-template-page-mapping.md)의 각 P01~P20에 구체적인 관리자 반영 시험을 기록했다. 공통으로 대상 ID·편집 UI·원래 값 위치를 먼저 확인하고, 합성 테스트 변경→저장→로그인/비로그인 화면·캐시 비교→원복→화면 복구 순서로 수행한다.

- P01: 홈 지정·슬라이드와 sidebar-home 위젯을 분리 검증. 홈 편집기 숨김 조건을 무시하지 않음.
- P02/03/04/18: 제목·필터된 본문·본문 이미지, 실제 members 값이 있으면 그 반복 구간.
- P05/12: 목록 페이지의 선택 필드와 각 제품의 제목/대표 이미지/price_label·정렬/페이지 처리.
- P06~11/13~15/17: post title과 room_name을 따로, slider/본문/attributes/CTA 값을 각각 대조.
- P16/19: 본문·이미지·링크·주문 정책/이메일 안내. 새 주문 폼 전환 시험이 아님.
- P20: 기존 폼 제공자·shortcode·폼 정의·필드/첨부/결과·필터 유지.

## 시험 기록 양식

시험 ID / P번호·URL / KST 시각 / 로컬 스냅샷·코드 버전 / WP·PHP·플러그인 / 대상 post ID·템플릿 / 변경 데이터의 분류(실제 값 기록 금지) / 기대·관찰 결과 / 비식별 로그·캡처 / 원복 확인 / 통과·실패·미실행·미확인 / 담당자를 기록한다.

## 중단 기준

핵심 URL·제품 조회 누락, 관리자 저장 불가, 폼 계약 변경·첨부/메일 실패, 운영 연결·실제 발송 발생, 개인정보 노출·보안 문제 발견 시 확대 테스트/배포를 중단하고 원인과 범위를 확인한다. 미실행 항목은 통과가 아니다. 신규 백엔드 구현으로 임의 우회하지 않는다.
