# 프론트엔드 변경 경계

작성일: 2026-10-29 (KST) · 상태: 사전 분석 / 구현·배포 미승인

**확인**은 로컬 코드 또는 기존 audit의 수집 사실, **후보/추정**은 구조 일치에 따른 해석, **미확인**은 운영 설정·DB·실행 검증이 필요한 항목이다. Holiday의 실제 활성 여부는 미확인이다. 서버·DB에 접속하거나 PHP를 실행하지 않았으며 새 백엔드·테마·UI를 구현하지 않았다.

## 기본 원칙

기존 PHP를 정적 HTML로 교체하지 않는다. 18px 중심·큰 버튼·짧은 메뉴·확대·명확한 주문/문의는 [모바일 기획](../proposal/11-mobile-senior-ux.md)의 제안이며 내부 컨펌 후 로컬에서 적용 범위를 결정한다. 지금 안전하다고 확정된 수정 대상은 없으며 아래는 영향 수준별 후보 경계다.

## 표시 후보와 기능 계약

위 표의 기능·메타·폼 계약은 [의존성](03-backend-dependencies.md)에 코드 근거를 기록했다. 래퍼·클래스도 JS 선택자이면 기능에 속한다. 단순 class 이름 정리로 취급하지 않는다.

## PHASE D에서 가져올 것과 가져오지 않을 것

[preview](../../preview/index.html), [검증 범위](../../preview/VALIDATION.md), [기존 명세](../13-frontend-specification.md)를 참고한다.

- 가져올 후보: 디자인 토큰 개념·레이아웃·버튼/카드 형태·큰 사진 보기/포커스 동작 계약·페이지 정보 순서. 승인 후 실제 데이터 출력 바깥에 적용한다.
- 가져오지 않을 것: page-map.json/HTML의 고정 콘텐츠·임시 이미지·테스트 필수 규칙·모의 성공/실패 처리·AP 체크·내부 검토 배너·운영 원문 배열.
- preview의 role=form·type=button은 비전송을 위해 만든 구조다. 실제 CF7/기존 서버 폼을 이 구조로 교체하면 안 된다.
- preview의 connect-src none/form-action none CSP를 운영에 복사하면 AJAX·문의·결제 등 기존 기능을 차단할 수 있다. 배포용 정책으로 전용하지 않는다.
- 모의 input ID는 실제 계약과 다르다. 모의 textarea가 좋다는 이유로 실제 폼 태그/필드 구조를 바로 바꾸지 않는다.
- 사진 슬라이더와 새 모달이 같은 버튼을 동시에 처리하지 않게 책임을 분리해야 하나, 구체 코딩·기존 JS 제거는 이번 단계에서 하지 않는다.

## 기존 관리자 편집을 보존하는 방법

새 소개·카드·사양을 프론트엔드 문자열로 고정하지 않는다. 기존 title/content/ACF/위젯/옵션 중 실제 소유 필드에 연결한다. 새 저장 필드가 필요해 보이면 지금 생성하지 않고 기존 필드로 표현 가능한지 먼저 분석한다. 본문 이미지를 개별 갤러리로 재구성하는 것은 CSS만의 문제가 아닐 수 있다. 기존 본문 HTML·쇼트코드·링크·전사 정보를 어떤 기준으로 보존할지 승인해야 한다.

## URL·데이터 변경 금지선

페이지/게시물 ID·post_type·post_name·rewrite slug·with_front·분류·필드 key/name·메뉴 location·첨부 ID·저장 테이블·폼 API/결과 형식·이메일 전송 계약은 기본 변경 대상이 아니다. 고유주소 저장/flush·도메인 정규화·일괄 치환·ACF 업그레이드도 별도 승인 없이 수행하지 않는다.

## 추가 위험과 결론

내장 ACF·고정 include·레거시 JS·동적 CSS·업로드 본문·짧은 PHP 태그·외부 분석 코드가 있다. 제거/업그레이드를 임의 수행하지 않는다. 보안 결함이 실제로 확인되면 현상 유지와 안전성 사이의 충돌을 문서화하고 별도 결정한다. [실행 준비](07-implementation-readiness.md) 전 코드 수정은 시작하지 않는다.
