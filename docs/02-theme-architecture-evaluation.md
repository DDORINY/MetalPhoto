# 테마 아키텍처 평가

작성일: 2026-10-26. 근거: [현재 상태 분석](01-current-state-analysis.md). 이번 문서는 구조 선택을 위한 평가이며 구현 승인이나 배포 승인이 아니다.

## 판단 전제

확인된 원본은 테마 10개이며 활성 테마와 DB·플러그인·전체 이미지가 미확보 상태다. 공개 HTML에는 Holiday 리소스 사용 정황이 있으나 실제 활성 구성을 확정하지 않는다. 현대적인 전체 UI/UX가 목표지만 콘텐츠·게시판·문의·서버 기능의 보존이 우선한다.

## 접근법 비교

| 접근법 | 장점 | 단점과 위험 | 적용 조건 |
|---|---|---|---|
| 기존 테마 직접 수정 | 기존 마크업과 동작을 따라가기 쉽고 작은 변경이 빠름 | 업데이트 시 변경 유실, 원본과 차이 추적 어려움, 기능·스타일 결합 누적 | 별도 개발 복사본에서만 제한적으로 검토. 다운로드 원본 직접 수정은 금지 |
| Child Theme | 부모 원본 보존, 변경 파일 범위 명확, 일부 템플릿·스타일 확장 가능 | 부모 의존성 유지, 부모 업데이트 회귀 가능, 고정 include나 함수 구조에 따라 override 제한 | 활성 부모가 확인되고 변경 범위가 부모 구조에 수용될 때 |
| 독립 Custom Theme | 정보 구조·접근성·스타일·리소스를 일관되게 설계 가능 | 기존 템플릿·쇼트코드·데이터 기능 누락 위험, 개발·검수 범위 증가 | 기능 의존성을 분리하고 콘텐츠 매핑·회귀 기준을 확보한 후 |

## 소스에서 드러난 선택 제약

### Holiday가 사용 중인 경우

`functions.php`가 내장 ACF, `includes/post-types.php`, 예약·AJAX·쇼트코드 등을 직접 불러온다. 독립 테마로 바꾸면 기존 `room_post`, `service_post`의 표시와 관리, 필드 해석, 예약 관련 기능이 영향을 받을 수 있다. DB 데이터가 남아 있어도 등록 코드가 없어 관리 화면에서 보이지 않을 수 있다.

단기적으로는 자식 테마에서 표시를 재구성하는 안을 평가한다. 장기적으로는 실제 사용하는 기능만 별도 사이트 기능 플러그인으로 분리하는 안을 검토할 수 있다. 내장 ACF와 별도 ACF를 동시에 로드하는 식의 단순 복제는 피하고, 필드 키·저장 구조·기존 버전과의 호환성을 검증해야 한다. 기능 분리는 아직 승인·구현되지 않았다.

### Notes and Photos가 사용 중인 경우

`style.css`의 `Template: blogrid`로 이미 자식 테마임이 확인됐다. WordPress의 일반적인 부모·자식 구조 아래에서 자식의 자식을 추가하는 방식을 전제하지 않는다. 별도 개발 복사본에서 기존 자식 테마를 확장하거나 부모·자식 변경분을 분석한 뒤 독립 테마로 이관한다.

### 나머지 테마가 사용 중인 경우

PHP 템플릿·콘텐츠 출력은 재사용 후보이다. 다만 메뉴 JS, FlexSlider·Slick·Masonry 같은 라이브러리와 클래스 선택자가 연결되어 있으므로 CSS만 교체해서 모든 동작이 보존된다고 가정하지 않는다. Twenty Nineteen의 기존 빌드는 실제 실행 전 도구 호환성 검토가 필요하다.

## 현재 자료로 권장하는 방향

**지금 확정할 것은 원본 보존과 격리 개발이며, 최종 부모 테마 선택은 보류한다.** 활성 테마 확인 후 아래 순서로 결정한다.

1. 사용 중인 템플릿·필드·플러그인·쇼트코드와 페이지를 매핑한다.
2. 자식 테마에서 홈·헤더·상세 페이지를 구현할 수 있는지 검토한다.
3. 변경 범위가 부모 구조에 수용되면 자식 테마를 우선한다.
4. 구조 충돌이 크거나 기능 분리가 필요하면 독립 Custom Theme의 비용과 회귀 범위를 비교한다.

## 권장 개발 구조 제안

아래는 향후 구조 제안이다. 이번 작업에서는 `docs` 외 폴더를 생성하지 않는다.

```text
C:\MetalPhoto\
├─ themes\                   # 다운로드 원본 보존
├─ docs\                     # 분석·요구사항·결정 기록
├─ backups\                  # 비공개 백업, 버전 관리 제외
├─ local-site\               # 별도 WordPress와 로컬 DB
└─ development\
   └─ metalphoto-theme\      # 최종 구조 결정 전 임시 명칭
      ├─ style.css
      ├─ functions.php
      ├─ front-page.php
      ├─ template-parts\
      ├─ inc\
      └─ assets\
         ├─ css\
         ├─ js\
         └─ images\
```

스타일은 디자인 토큰·기본 요소·공통 구성요소·페이지별 스타일로 나눈다. 기능 코드는 실제 소유 주체를 확인한 뒤 테마와 플러그인에 배치한다. DB·설정·접속 정보·원본 백업을 공개 저장소에 포함하지 않는다.

## 결정이 필요한 항목

| 결정 | 필요한 근거 | 현재 상태 |
|---|---|---|
| 최종 부모 및 자식 구성 | 관리자 활성 테마, template·stylesheet 확인 | 미확인 |
| 독립 테마 필요 여부 | 페이지별 구조와 기존 기능 의존성 | 보류 |
| 기능 플러그인 분리 범위 | 실제 게시물 유형·필드·예약 사용 내역 | 보류 |
| 개발 빌드 도구 | 로컬 도구 설치 상태와 호스팅 배포 제약 | 미결정 |
| 기존 라이브러리 교체 | 사용 화면·상호작용·접근성 실측 | 미결정 |
