# 개발 로드맵

작성일: 2026-10-26. 현재 완료 범위는 이전 테마 조사·공개 링크 조사 및 최초 문서화다. 아래 실행·환경 설치·자료 다운로드·배포는 이번 작업에서 수행하지 않았다.

| 단계 | 주요 작업 | 산출물 | 완료 기준 / 의존성 |
|---|---|---|---|
| 1. 실사이트 조사 | 승인된 공개 화면 조사, PC·모바일 흐름 확인, 관리자에서 활성 테마 확인, 자료 확보 범위 협의 | 페이지별 현황표·화면 기록·기능 목록 | 20개 알려진 경로와 추가 발견 경로를 구분. 화면 미확인 평가 제거 |

## 단계 1에서 확보할 자료

- 활성 테마 이름·부모 관계·버전, WordPress·PHP 환경 정보.
- 운영 담당자가 안전하게 제공하는 DB 복사본·플러그인·uploads 및 별도 추가 CSS.
- 홈·글 목록 설정, 메뉴·위젯, 각 페이지의 템플릿 배정.
- 실제 사용 중인 게시판·주문·문의·예약·메일 연동 목록.
- 원본 이미지 사용권과 외부 서비스 연동 범위.

자료에는 개인정보가 포함될 수 있으므로 비공개 보관하고 문서에 실제 DB 값·접속 정보·고객 데이터를 넣지 않는다. 이번 작업의 서버 접속 금지는 자료 확보 작업에도 그대로 적용된다.

## 구현 순서와 구조 결정

활성 구성 확인 → 기능 의존성 표 작성 → [아키텍처 평가](02-theme-architecture-evaluation.md)에 따라 방식 선택 → 공통 헤더·푸터 → 홈 → 제품군 → 제품 상세·사례 → 회사·기술 → 문의·주문 순서로 진행한다. 문의 흐름의 기술 검증은 초기에 함께 수행해 뒤늦은 기능 누락을 방지한다.

페이지 이름이나 메뉴는 바꿀 수 있지만 기존 URL을 자동으로 변경하지 않는다. 새로운 화면이 기존 게시물 ID·필드·첨부 파일을 읽는 구조를 우선한다. 전체 DB를 과거 복사본으로 덮어쓰는 배포는 피하고 콘텐츠 변경분과 코드 변경분을 구분한다.

## 배포·롤백 계획의 필수 조건

배포는 향후 별도 승인 작업이다. 승인 요청 전에 실제 변경 파일 목록, 검수 결과, 복구 가능한 코드·DB·uploads 백업, 복원 절차, 점검 시간과 담당자를 준비한다. FTP/SFTP 파일 수정·업로드·삭제 금지는 유지하며, 다른 배포 방식도 사용자와 합의하기 전 실행하지 않는다.

롤백은 테마 파일 복구뿐 아니라 메뉴 배정·위젯·테마 옵션·DB 스키마 변경의 유무를 포함한다. 운영 중 신규 문의·주문이 쌓일 수 있으므로 DB 전체 복원 여부를 별도로 판단한다. 폼 실패·핵심 콘텐츠 누락·중요 경로 오류 등 중단 기준을 사전에 정한다.
