# 홈페이지 리디자인 요구사항

작성일: 2026-10-26. 페이지 주소는 이전 대화에서 확인한 공개 메뉴·본문 링크 20개를 그대로 사용한다. 이번 문서 생성 중 재조회하지 않았다.

## 목표와 평가 범위

제품·기술·실적을 이해하고 적절한 문의·주문 경로에 도달하기 쉬운 반응형 홈페이지를 만든다. CSS, PHP 템플릿, 페이지 구성, 전체 UI/UX가 범위다. 기존 콘텐츠·이미지·URL·게시판·문의 기능을 보존한다.

**현재 디자인에 대한 시각적 평가는 수행하지 않았다.** 아래 역할과 개편 방향은 공개 메뉴명 및 소스 구조를 기반으로 한 기획 제안이다. 실제 본문·이미지 품질과 사용자 흐름은 화면 조사 후 평가한다.

| 정보 계층 | 첫 화면에서 페이지 목적과 다음 행동을 파악 가능 | PC·모바일 화면 및 사용자 흐름 검토 |

## 반응형 요구사항

- 360·390·768·1024·1440px 폭을 대표 검증 지점으로 사용하되 실제 기기와 콘텐츠에 따라 조정한다.
- 본문과 메뉴는 의도하지 않은 가로 스크롤 없이 표시한다. 긴 표는 별도 스크롤 영역으로 제공한다.
- 모바일 메뉴는 키보드 조작·열림 상태·포커스 복귀를 지원한다.
- 브라우저 확대를 허용하고 200% 확대에서도 주요 콘텐츠와 조작을 유지한다.
- 사진은 반응형 크기를 사용하고 상품 판단에 필요한 부분이 잘리지 않도록 한다.
- 터치 대상은 충분한 크기와 간격을 확보한다. 목표 44×44 CSS px를 기본으로 검토한다.
- 자동 재생·과도한 모션은 필요성을 검토하고 사용자 모션 감소 설정을 존중한다.
- 성능은 먼저 기준 화면을 측정한 뒤 이미지·폰트·스크립트 예산을 결정한다. 현재 성능 점수는 미측정이다.

## 기능 보존 요구사항

1. 기존 페이지 ID·게시물·첨부 파일·분류·필드 값을 보존한다.
2. 20개 경로를 기준으로 페이지별 이전/이후 응답·콘텐츠·문의 진입을 비교한다.
3. 게시판·폼·첨부·메일·주문 관련 실제 사용 기능을 먼저 식별한다. 존재하지 않은 기능을 구현 완료로 간주하지 않는다.
4. Holiday 기능 사용 시 CPT·ACF·쇼트코드·예약 의존성을 보존한다.
5. `wp_head`, `wp_footer`, 콘텐츠 필터 등 플러그인 연결 지점을 유지한다.
6. 로컬 테스트는 운영 DB·실제 메일·결제·문자·외부 웹훅과 분리한다.
7. URL 변경은 기본 범위에 포함하지 않는다. 필요한 경우 승인된 리다이렉트 매핑과 SEO 검수를 선행한다.

## 근거 및 결정 대기

근거는 이전 공개 메뉴·본문 링크와 [로컬 소스 분석](01-current-state-analysis.md)이다. 화면 품질·콘텐츠 적합성·이미지 원본·폼 처리·검색 색인은 미확인이다. 디자인 톤, 대표 콘텐츠, 제품 비교 항목, 문의 우선순위와 대표 도메인은 운영 담당자와 결정해야 한다.
